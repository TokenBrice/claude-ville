# Smoke and runtime verification catalog

These checks complement `node:test`. Most are deterministic Node programs; browser checks use Playwright, and some target the maintained dashboard at `http://localhost:4000`. Fixture-backed scripts honor `CLAUDEVILLE_TEST_TMPDIR`. Runtime estimates are typical local runs. "Isolated socket" means an OS-assigned port, never port 4000.

| `webgpu-parity.mjs` | 10.1 Stage A gate (WebGPU contract §5): one page, both backends, one frozen frame context. The terrain bake's CPU canvas is kept for the page (B.2 would release it to a GPU-only stand-in a fresh renderer cannot sample). Metric per target: per pixel `d` = max RGBA \|webgl − webgpu\|; share(d ≤ 1), share(d = 0), maxAbsDiff, histogram, the 100 worst pixels, and `rimTier` (pixels a record samples from a source texel with 0 < a < 255, 1-px dilated). **Pass: composite share(d ≤ 1) ≥ 99.9 % in every case**; a failure whose > 1 LSB pixels all lie in `rimTier` is `P1-limited` (still a failure, §3.3). Controls: the WebGL2 reference is rendered twice around the WebGPU frame (`glStable` must hold) and the app's own world replays the same context (`appReplay`, informational); light admission, mark records and the fat gate are compared per backend in the report. Matrix (§5.3): readme-showcase 12:00 z2 and 22:00 z3, midnight-oil 22:00, storm-night-reduced-motion (storm 22:00, reduced motion), git-harbor 19:45 z1, dense-100-agents 12:00 and 22:00 z1, failed-push 18:00, many-waiting 22:00 (marks), release-parade 09:00, and readme-showcase 14:00 z1 frozen mid clear → rain transition at cloud cover 0.37 and 0.50 (weathers `clear-rain-35` / `clear-rain-50`: every cloud course and the sea's sunlit course has edges on screen) — each at 1920×1080 (backing 1680×1032), 5120×1440 (4880×1392) and 1512×982 DPR 2 as a flight frame (zoom 1.37, sub-pixel offset: k = 2.74, the fat-pixel path; `fat` column); `--case=scenario:hour:weather:zoom[:reduced]` runs ad-hoc cases. Two live pages never share the cloud courses' drift (`Wind.cloudCourseDrift` integrates each page's own frame history), so a two-page motion comparison must pin it; the frozen context here shares it. Also the device-loss check (§5.4: on the app's own world, booted `?renderer=webgpu`, `device.destroy()` makes `isActive()` false within ≤ 3 frames (`device.lost` resolves asynchronously and no synchronous signal exists; the canvas holds the last good frame meanwhile) and the app hands over to a fresh WebGL2 world within 7 frames after (≤ 3 frames of slack over the three idle tasks that build it, re-bake the terrain and draw its swap frame while the loop holds the last frame) with a visible fx canvas and a `webgpu failed in frame: device…` reason (`fallbackOk`); on a harness-built renderer, `getDiagnostics().deviceLost` carries a reason and the frame after `_rebuildDevice()` is within the gate of the frame before) and `--burst`: `gpu-burst.mjs --renderer=webgl|webgpu` level 0 at 1680/4880 with host load recorded (a receipt only when load < 4; recorded, not gated). A missing module, method or target is `n/a`, never a crash. Writes `report.json` and per case `webgl.png`, `webgpu.png`, `diff-<target>.png` (d = 0 dimmed luma, 1 blue, 2–3 yellow, ≥ 4 red, rimTier > 1 magenta). Exit 0 = every case measured and passing, 1 = a failure, 2 = nothing failed but something was `n/a` (not a gate pass). ## Change-to-check matrix

| Change | Focused checks |
| --- | --- |
| Identity/sprite mapping | `npm run models:check`; `npm run models:resolve -- <provider> <model>`; `npm run sprites:audit-ids` |
| Sprite pixels/channels | `npm run sprites:audit-refresh`; optionally `npm run sprites:capture-fresh` then `npm run sprites:visual-diff` |
| Panel DOM | `npm run test:unit`; `node scripts/smoke/ui-remediation.mjs` against the maintained server |
| World rendering | `npm run verify:render`; `npm run world:validate-buildings`; `npm run world:validate-terrain`; performance via `npm run world:benchmark-fps` or `npm run world:benchmark-trails`; ladder and `EFFECT_BUDGET` receipts (quiet host) via `node scripts/smoke/world-fps-benchmark.mjs --mode=soak\|inject\|dashboard\|kslope\|unlocked` and `npm run world:gpu-burst` |
| WebGPU backend / WGSL twins | `npm run smoke:webgpu-parity` (the 10.1 gate; `--scenarios`/`--sizes` for a quick subset, `--burst` for the FULL cost comparison) |
| Adapter parsing | `npm run check:adapters`; `npm run check:adapter-fixtures`; `npm run test:unit`; `node scripts/smoke/adapters.mjs` |
| Server API/WebSocket | `npm run check:server`; `npm run test:integration`; `npm run verify:server` |
| Pricing | `npm run models:check`; `npm run test:unit`; `npm run models:resolve -- <provider> <model>` |
| Sound/audio | `npm run test:unit`; `npm run verify:render` (the sound control); `npm run audio:probe` (local gate, not in CI) |
| Docs/catalogs | `node --test scripts/tests/catalog-check.test.mjs`; review the diff |

Use `npm run validate:quick` for the broad deterministic loop, `npm run validate:full` for integration/server/World validation, and `npm run gate:release` for release metadata plus gates. Playwright checks are opt-in and require installed dev dependencies.
