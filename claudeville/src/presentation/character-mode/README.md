# World Mode Renderer

World mode is the isometric view ClaudeVille shows by default. It renders through one of three backends, chosen once per page: the resident WebGPU world (`gpu/GpuWorldRendererWebGPU.js`, the Chromium default), the resident WebGL2 world (`gpu/GpuWorldRenderer.js`, Safari, Firefox, and any Chromium where a WebGPU step fails), or the Canvas 2D world (a software rasterizer, no WebGL2, or `?renderer=canvas`). See *Renderer selection* below. This directory owns the render loop, sprites, camera, and particles. It reads from the domain `World` and listens to the event bus; it never mutates domain state.

The directory is named `character-mode/` for historical reasons. In prose, the user-facing surface is "World mode" (paired with "Dashboard mode" under `../dashboard-mode/`).

## Data sources and draw order

World mode is driven by four source layers:

- Domain state from `World` (`agents` and `buildings`).
- Static config from `src/config/constants.js`, `buildings.js`, `townPlan.js`, `scenery.js`, and `theme.js`.
- Sprite metadata from `claudeville/assets/sprites/manifest.yaml` and `palettes.yaml`.
- Runtime provider state already normalized into `Agent` objects, including `gitEvents` for harbor activity.

The frame (`WorldFrameRenderer.renderWorldFrame`) runs one sequence on every backend. The two resident GPU worlds (WebGPU, WebGL2) share every CPU step and differ only inside `gpuWorld.render`; the Canvas world (with or without the hybrid PostFx pass) diverges where the table says. The T1 mark pass and the late mark pass draw after the composite, straight onto the presented frame, so no grade, flash, bloom or particle reaches them. `markRecords` / `markRoleRecords` count the frame's T1 records (role-2 = `GPU_RECORD_FLAGS.actionMark`); the overlay prints only the plate ink when `markRecords` equals the frame's mark count, else it draws the whole plate. The late pass runs after the moment edge plates in the same task (`drawPeakMarks` → `handPeakMarksToGpu`): the verified-success cream peak texels (`takePeakMarks`, as role-2 `mark:inks` records from `inkMarkRecords`) followed by the frame's T1 marks again, collected in `renderer._lateMarkRecords`, so the marks stay above the cream as the overlay stacks them. It is armed only when the GPU frame rendered at an integer DPR with the overlay's backing size (`peakMarksArmed`); if `drawLateMarks` returns fewer than `_lateMarkRecords.length`, the overlay paints the cream back where `peakMarkSink` cleared it. Canvas draws everything on the overlay.

Layer detail:

1. Backdrop on the 2D canvas: the stepped sky plate, painted in final C2 colours on the resident GPU path (where `BackdropGrade` lays the scene's vignette courses and aerial haze over it) and in its preimage (`ungradeRgb`) on Canvas, whose frame grade then lands it on the same colours. On Canvas the backdrop also carries the open sea (`drawOuterOcean`, preimage, world-anchored fills); on the resident path the composite paints the sea (5.).
2. The terrain cache: the `ground-splat` bake and its far-row haze, then the `coast` stage (baked water ramp per world texel, foam lace, outer shelf, the SW/SE shoreline mass; painted after the haze so every water, foam and wet-sand texel is an exact CoastBake colour), bridges, foundations, flat features, then the `finish` stage (3.7 static reflections over all of them, then the resident water fields). It carries no time of day. On Canvas (3.12) `_drawTerrain` then draws, in world space: the water mood copy (`drawCanvasWaterMood`) and `CanvasWaterState`'s layers (`drawCanvasWaterState`: the sea body and sunlit course, the step overlay with reflection ripple, caustics or the static dashes, near-shore / river current and deep swell crests on in-map water and the open sea, specks, rain rings, swash; the Lighthouse sheen and the sun/moon path), and builds the 2.9 lamp columns that land on the overlay after the grade (`drawCanvasWaterColumns`); the resident scene and composite shade the same rules per fragment.
3. Ground records: live ground cues, building and tree casts, and villager contact shadows and rings. On the resident path `buildGpuWorldRecords` orders them right after the terrain record (`terrain:static`, then every `ground:*` record, then the rest).
4. The depth-sorted pass: props, building bases and occlusion-aware hero pieces, agents, landmark activity, building fronts, and every world particle at its spawn sortY. On the resident path the overlay-safe scene categories (Harbor traffic with wildlife, landmark activity, bridge lanterns) are skipped here and drawn once on the overlay, and Harbor hulls travel as native records. A body whose feet fall between a split building's back and front depths, behind its footprint, sorts before the back half so the whole building hides it. On the resident path the records are V9 instances (`docs/material-channel-contract.md`): opaque sprite records write a 16-bit painter depth (`always`, so painter order still decides colour), then the particles draw once with less-equal and no depth write, so a particle behind a nearer building front or body is hidden.
5. The grade: on the resident path the scene pass grades each albedo fragment with C2 before the light loop, adds the stepped multiplicative pools and authored emission after it, and shades each record's world-locked cloud courses and screen-Y aerial haze on its own texel grid; the composite then paints the open sea (3.3/3.4) under every scene.a < 1 pixel below the horizon with the in-map water's own pipeline (stop, crests, path, mood, cast, grade, cap, sky courses, vignette, fog, cloud courses, cat's paws, squall), with the Lighthouse beam's dashes on the sea, then the flash and bloom. The Canvas fallback reproduces the same grade with composite fills (`CanvasGrade`); the hybrid PostFx pass grades the finished 2D frame, lays its pools through the V5 receiver mask and blooms only the emitter cuts' own emission (the 2.9 water columns and the cuts land on the overlay just before this pass, which reads their emission).
6. The ungraded upper overlay, in the order of step 9 above. Director overlays draw ground rings only for the selected building and incidents, as static 1-texel pixel outlines (no team, lifecycle, or per-building signal halos); T3 plaques treat the lower-third caption strip as occupied (its box is published as the reserved `caption-band`); the letterbox is neutral brass (no glide grade: nothing tints the frame); T1 plates draw after the letterbox so no bar can hide an agent that needs you.

On the resident path the T1 attention marks split across the stack (Wave 10 S5, `docs/material-channel-contract.md` "T1 mark records"): their graphics (leader, beacon, rim, status cell, text cell, notch, edge arrow) are V9 `screenSpace` records in the mark pass; at the plate slot the overlay clears exactly their footprint and prints only the word, name and time. The page is byte-identical to drawing the whole plate on the overlay, which Canvas, a non-integer DPR and any frame whose mark pass did not draw every record still do. The mark pass is also where 10.2 lifts the action-needed marks on an HDR screen and 10.3 widens their gamut on a P3 screen (below); on an SDR sRGB screen it writes each texel unchanged.

World mode renders through a three-canvas stack inside `#characterMode`: `#worldCanvas` (the 2D scene, source of truth and mouse target), `#worldFxCanvas` (the WebGPU or WebGL2 output, hidden whenever inactive), and `#worldOverlayCanvas` (2D UI: weather foreground, marks, labels, moments, letterbox, debug — never graded or distorted). The canvases stay at opacity 0 until the renderer emits `world:first-frame`, then fade in (360 ms on boot, 220 ms back from Dashboard, no fade under reduced motion) over the container's stepped bands (see the boot and first-frame contract under Event-bus integration). Grading ownership is exclusive: when a GPU stage is active the 2D grade and pool stamps are skipped and the GPU grades from the same C2 `lightGrade`; when inactive (`?postfx=0`, no WebGL2, context loss, or ladder level 3) the Canvas fallback grades the finished frame itself. Shift-D shows post-FX level and timings. The resident GPU path replays only functional building marks and occupancy pennants on the upper Canvas in drawable depth order; authored manifest layers and atmospheric building reactions remain owned by the GPU path.

The renderer may replace `#worldFxCanvas` (the live WebGL2→WebGPU switch, a WebGPU start failure, a failure fallback) and does so only through `IsometricRenderer._replaceFxCanvas()`, which gives the new element the live one's CSS box and `_claudeVille*` resize bookkeeping; `App`'s resize resolves all three surfaces from the DOM on every call, so a replaced canvas keeps tracking resizes, the sidebar toggle and the Activity Panel. The panel's 1 px seam is its own left border (not an outer shadow over the world), so the world, fx and overlay canvases all show the same last column.

**Renderer selection.** `show()` picks the World backend once per page. `?renderer=canvas` gives the Canvas world (with the hybrid PostFx), `?renderer=webgl` forces the resident WebGL2 world wherever WebGL2 exists, `?renderer=webgpu` forces the WebGPU world where it can start (below), and `?postfx=0` gives the Canvas world with no GPU layer. An explicit value always wins. With no flag (an empty or unknown `?renderer=` value counts as none: only exactly `webgl`, `webgpu` or `canvas`, any case, skips the probe; `GpuWorldPolicy.forcedGpuWorldRendererMode`), `GpuWorldPolicy.resolveGpuWorldRendererMode` decides in this order: a software WebGL2 rasterizer or a fallback WebGPU adapter takes the Canvas world; a Chromium browser (`isChromiumBrowser`: `navigator.userAgentData.brands` names Chromium or Google Chrome, else the UA string) whose WebGPU adapter, device and pipelines resolved takes WebGPU (10.1 Stage B); otherwise a hardware WebGL2 rasterizer takes WebGL2, so Safari (WebGPU stays opt-in until the parity harness runs in Safari itself) and Firefox default to WebGL2, as does Chrome when any WebGPU step fails. `GpuWorldRenderer.probeWebgl2Raster()` probes throwaway canvases and treats the rasterizer as software when the browser refuses a `failIfMajorPerformanceCaveat` context or the unmasked renderer string names SwiftShader, llvmpipe, softpipe, lavapipe or the Microsoft Basic Render Driver (`GpuWorldPolicy.isSoftwareRasterizer`). The resident scene and composite programs are uber-shaders. A software rasterizer pays for every branch of them, so on headless Chromium's SwiftShader the first frame JITs for about 3 s and each frame then costs about 200 ms of GPU time, with the main thread blocked on every frame's readback. The Canvas world draws the same scene there at about 50–70 ms a frame. `renderer.worldRendererMode` reports the choice (`webgl`, `webgpu` or `canvas`) and `renderer.worldBackendReason` why (Shift-D's first row, and one `[IsometricRenderer] world backend:` console line per choice). Plain headless Chromium (`npm run verify:render` and the other smokes) has no WebGPU adapter and a SwiftShader WebGL2, so it captures the Canvas world. Tools that need the resident path launch with `GPU_LAUNCH_ARGS` (`scripts/smoke/support/world-bench.mjs`), which now defaults to WebGPU; a WebGL2 measurement passes `?renderer=webgl` (`--renderer=webgl` on `gpu-burst` and `world-fps-benchmark`).

**WebGPU backend (Wave 10, 10.1; the Chromium default since Stage B).** Safari stays opt-in (`?renderer=webgpu`), Firefox stays WebGL2. `App.boot` calls `IsometricRenderer.prewarmBackend()` as soon as the renderer module loads, so the WebGPU world resolves beside the asset fetch (`GpuWorldPolicy.shouldProbeWebGpu`: `?renderer=webgpu`, or no forced mode in a Chromium browser with `navigator.gpu` and a hardware WebGL2 rasterizer); `App._loadRenderer` then awaits `IsometricRenderer.resolveBackend()`, which takes that resolution over, before the synchronous `show()`. The resolution loads `GpuWorldRendererWebGPU.js`, requests a hardware adapter (a fallback adapter counts as software and takes the Canvas world) and a device with the adapter's own `maxSampledTexturesPerShaderStage`, `maxSamplersPerShaderStage`, `maxInterStageShaderVariables`, `maxColorAttachmentBytesPerSample` and `maxStorageBuffersPerShaderStage`, and compiles every module and pipeline, including every non-role scene variant and the no-emission particle pipeline, asynchronously (`prepareGpuWorldWebGPU`; a frame never compiles one). Any failure there resolves to WebGL2 first, Canvas second, before a canvas context is taken; a WebGPU renderer that still fails to start swaps in a fresh `#worldFxCanvas` for WebGL2. `?renderer=webgpu` waits for the resolution; the default never does: on a warm shader cache it has settled by the mount (measured at +30 ms over `?renderer=webgl` to the first world frame), and one still compiling at the mount (a cold cache, the first boot after a WGSL, browser or driver change: about 2 s measured) mounts WebGL2 and switches when it is ready. The switch (`_queueWebGpuSwitch`, `_beginWorldSwap`, `_endWorldSwap`) waits for the reveal and a healthy WebGL2 world, builds the WebGPU world on a fresh fx canvas off the document, renders one loop frame on it and, only if that frame drew, replaces the WebGL2 canvas in the same task and disposes the WebGL2 world; a frame that did not draw keeps WebGL2 (and retries while the WebGPU world is healthy). Per frame: the scene MRT (rgba8 colour + rgba8 emission; the emission target is rgba16float only while HDR presents, below) with a transient `depth16unorm` painter depth (`depthCompare: 'always'`, per-batch depth write in the pipeline key) and the particles at `less-equal`. Every offscreen target is drawn in GL's row order (clip y negated, row 0 = the frame's bottom, exactly ANGLE-Metal's FBO memory), because a nearest tap that lands on a texel seam resolves by row order: the scene and particles (`sceneVs`, `particleVs`), then the bloom chain, sampled with GL's own bottom-left uv. The present pass draws the canvas unmirrored: the composite reads the scene with `textureLoad` at row `H - 1 - y`, then the open sea, the debug load and the S5 T1 mark pass (`markVs`), onto `bgra8unorm` with `alphaMode: 'premultiplied'`. Canvas and image sources upload with `copyExternalImageToTexture({ premultipliedAlpha: false })`, measured byte-identical to WebGL2's `texImage2D` at every alpha (`output/waking-isle/WGPUCore/probe-bytes.html`; a getImageData decode is not); typed fields go through `writeTexture` from the same arrays. `device.lost` drops every handle without destroying it (the Canvas world draws meanwhile); a browser-caused loss rebuilds itself (`_rebuildDevice()`: a fresh adapter, device and pipelines, every texture re-uploaded from its source). **Failure fallback:** an unrecoverable failure — a frame that throws (a failed `submit`), a validation or out-of-memory error inside the frame's own error scopes (`_openFrameScope` / `_closeFrameScope` around its uploads, encode and submit, and around the late mark pass), an explicit `destroy()` that is not the world's own dispose, a failed rebuild — sets `failure` (`{ stage, message, summary }`) and the world goes inactive for good. An error outside those scopes (`device.onuncapturederror`: the browser's own work on the device, such as its copy of the canvas for a page readback) is logged and counted (`uncapturedErrors`, `lastUncapturedError`, Shift-D), never a failure. `IsometricRenderer._fallBackFromWebGpu` then hands over to a fresh WebGL2 world on a cloned fx canvas through the same swap: a frame that threw is rendered again on WebGL2 in the same task (its records were the GPU's, so the page never presents it); an asynchronous failure, found at a frame's start, holds the last presented frame (the loop draws nothing) while idle tasks build the WebGL2 world, re-bake the terrain canvas it uploads and draw the swap frame through `renderNow()` (`_stepFallbackPrep`), so no loop frame carries that work and the camera resumes with an ordinary step. A fallback swap also runs on an armed first frame, so a device lost during a Dashboard visit reveals the return on WebGL2. Without WebGL2 the session stays on the Canvas world (`_dropToCanvasWorld`; a frame that threw is drawn again on it in the same task). `worldBackendReason` then reads `webgpu failed in frame: <summary>`. A standalone world (the parity harness) may still `_rebuildDevice()` after a `destroy()`. `timestamp-query` spans feed the 0.1 ladder through `selectGpuTimingMetrics` exactly as the WebGL2 timer does (1 frame in 4, p25 of 30); `drain()` is `gpu-burst`'s GPU-finished hook (`--renderer=webgpu`) and `debugCaptureTargets()` the parity harness's readback (`scripts/smoke/webgpu-parity.mjs`; scene and emission rows flipped to top-left; an rgba16float target reads back as a Float32Array, `formats` names each). Declared exclusion: the 2.10 radiance solve is not ported (it is off at every level): `setRadianceOverride(true)` returns false and `getDiagnostics().radianceBounce` is false. `getDiagnostics()` adds `backend`, `adapter`, `canvasFormat`, `timestamps`, `deviceLost`, `failure`, `uncapturedErrors`, `lastUncapturedError`, `deviceRebuilds` and `recordStride`; its resource accounting counts each attachment at its own format's bytes per texel, including the configured canvas (`presentation`, rgba16float while HDR presents). A GPU-process crash (every 2D canvas lost) reloads the page once per two minutes (`App._bindGraphicsRecovery`; `docs/troubleshooting.md`).

nothing is multiplied by 1. **HDR (WebGPU only):** a display variant built asynchronously on first use (`GpuWgpuPipelines.displayVariant`: the roles composite module, the roles mark fragment, the debug load for the format; Budgets and bands: `docs/motion-budget.md`.

## Depth drawable contract

World mode overlap rendering goes through `DrawablePass.js`. New overlap-aware visual systems should adapt their items to this shape before entering the shared sorted pass:

```js
{
  kind: '<stable-category>',
  sortY: <finite-world-y>,
  sortBand: <optional-order-band>,
  stableKey: '<optional-deterministic-key>',
  salience: 'primary' | 'recent' | 'working' | 'ambient',
  materialId: '<stable-material-source>',
  materialClass: '<known-class>',
  elevation: { base: 0, top: 0, unit: 'sprite-px' },
  emissive: { strength: 0, sources: [] },
  occluder: { mode: 'alpha-silhouette', strength: 1 },
  atlasFrame: null,
  drawFallback(ctx, zoom, context) {},
  buildGpuRecord(context) {},
  hitArea: null, // optional future hit-test metadata
  payload: <source-object>
}
```

`kind` should be stable enough for diagnostics and narrow special cases such as the selected-agent x-ray pass. Ordering is `sortY`, then `sortBand`, then `kind`, then `stableKey`, then insertion sequence. `createDepthDrawable()` assigns default bands for building backs, props, harbor traffic, agents, landmark activity, chronicle monuments, familiar motes, and building fronts (the Chronicler has no kind: its Canvas-only body was removed in Phase 3); set `sortBand` only when a new category needs deterministic interleaving. Normalize missing or non-finite `sortY` before sorting. The legacy `draw()` property remains an alias of `drawFallback()`, so Canvas output is unchanged. `buildGpuRecordsFromDrawables()` converts the already-sorted stream and adds `drawOrder`; consumers may batch only consecutive compatible records. Avoid adding new manual draw switches in `WorldFrameRenderer.js` when an adapter in `DrawablePass.js` can preserve the existing behavior. Use `cullDepthSortedDrawables()` for large drawable sets that can be skipped outside the camera viewport.

Static props (`StaticPropSprite` in `StaticPropDrawables.js`: trees, boulders, district props, walls, the Village Gate) sort at their footprint world Y unless they pass an explicit finite `sortY`. A tall prop may `splitForOcclusion` into back and front halves so a villager can stand between them. A prop that ends a wall run must not split: its back half would sort before the run and the run would paint over it, so the sea tower (whose drum the east run ends in) draws whole at its foot − 8, after the run, at every zoom. A prop that is long along one tile axis cannot use one depth: the ends of the 9-tile gatehouse sit about 140 world px apart. Such a prop passes `occlusionColumns` from `lineOcclusionColumns()` instead. These are vertical slices of one cached image (16 px wide for the gate), and each slice sorts at the wall line's Y under its centre, so anything north of the wall paints first and anything south paints after. Both backends cut the slices with `columnSourceSpan()`. A column prop always draws from its cache, so a drawn-state change such as the gate doors must call `invalidateCache()`.

Material metadata is optional. Missing values normalize to unlit albedo, zero emissive contribution, a flat alpha-silhouette occluder, and no atlas frame. See [`../../../../docs/material-channel-contract.md`](../../../../docs/material-channel-contract.md) for manifest fields, stable material indices, atlas frame tags, channel encoding, and tooling.

`WorldFrameRenderer.js` still reaches into renderer private helpers for terrain, atmosphere, debug, labels, and post-processing. Treat that as a follow-up for layer extraction, not a reason to broaden a drawable-only change.

## Selection lifecycle

```
canvas click (IsometricRenderer._onClick)
  → camera.screenToWorld(x, y)
  → IsometricRenderer._handleClick(worldX, worldY)
      hit-test agentSprites, front-most first (gate departures skipped)
      ├── agent hit → sprite.selected = true
      │               camera.followAgent(sprite)
      │               onAgentSelect(agent) → App.js emits 'agent:selected'
      │
      ├── building instrument hit (Forge result tile, task-board plan tab)
      │             → selects that session through the same path
      │
      ├── monument hit → opens its stone ledger; onAgentSelect(null)
      │
      └── miss → camera.stopFollow()
                 onAgentSelect(null) → App.js emits 'agent:deselected'
                 then emits 'building:selected' for a building hit,
                 otherwise 'building:deselected'

eventBus 'agent:selected' (also emitted from Sidebar / DashboardRenderer / ActivityPanel)
  → App.js _bindAgentFollow → renderer.selectAgentById(agent.id)
  → ActivityPanel.show(agent) (the panel module and stylesheet load on the
    first selection), starts 2s detail polling

eventBus 'agent:deselected' (World miss, ActivityPanel close, Escape,
or 'agent:removed' for the current agent)
  → App.js → renderer.selectAgentById(null) → camera.stopFollow()
  → ActivityPanel closes
```

`onAgentSelect` is wired in `App.js` after the renderer is created and routes through `shared/AgentSelection.js` (`emitAgentSelected`, `emitAgentDeselected`). The renderer keeps a single `selectedAgent` reference; clearing it deselects every sprite and stops camera follow.

| `TILE_HEIGHT` | `32` | iso projection (half of width — standard 2:1 iso). |
| `MAP_SIZE` | `40` | square tile grid; terrain seed is `MAP_SIZE * MAP_SIZE`. |

## Event-bus integration

`IsometricRenderer.show()` subscribes to domain events and stashes the unsubscribe functions in `_unsubscribers` for teardown:

| Event | Effect on the renderer |
| --- | --- |
| `agent:added` | `_addAgentSprite(agent)` creates an `AgentSprite` and starts its arrival. |
| `agent:updated` | Applies the update to the sprite; a departed agent starts walking out, a session that returns mid-exit turns around at the gate, and one that returns after leaving arrives again. |
| `agent:removed` | Starts the departure for a sprite that has not already left. |
| `subagent:dispatched` | Queues the summon ritual. |
| `building:active-agents`, `building:selected`, `building:deselected` | Caches building presence tiers for emitter gating and invalidates the idle frame. |
| `camera:auto-camera` | Toggles the Auto camera. |
| `biography:updated` | Applies earned nicknames to name tags. |

While Dashboard mode is active, the agent handlers skip arrivals and departures and mark sprite state dirty; it is reconciled when World mode returns. Selection events (`agent:selected`, `agent:deselected`) are bridged in `App.js`, not subscribed here directly. The renderer exposes `selectAgentById(id)` for that bridge to call.

`mode:changed` is consumed by `IsometricRenderer` to call `setWorldModeActive(mode !== 'dashboard')`. When Dashboard mode is active, the World render loop stops and volatile renderer caches are released; when World mode becomes active again, dirty sprite state is reconciled and the loop restarts. Browser visibility and canvas context loss/restoration also pause, resume, and rebuild canvas-owned caches. `App.js` captures the camera pose on the switch to Dashboard and restores it with `camera.resumeViewPose` on return instead of re-framing. `ModeManager` switches modes as a cut inside one task (show the incoming surface, hide the outgoing one, emit `mode:changed`), so the Dashboard lays out and the World measures its last frame before the browser paints; there is no mode fade.

**Boot and first-frame contract (0.3).** The World never presents a black, stale-pose or pale frame:

- `world:first-frame` fires once per activation (`reason` `'boot'` or `'return'`) from `_signalFirstFrame`, right after a render in the same task, with `{ reason, sky, sea, horizonY, bands, cell }`: `sky` is the live sky palette, `horizonY` the sea horizon's screen fraction (0 when it is at or above the top edge), `bands` four `{ top, color }` stepped bands measured from that presented frame (seamed on the horizon when it is on screen), `sea` the frame's mean colour below the horizon, and `cell` the art texel in CSS px. There is no timer fallback: a renderer that never draws keeps the world hidden rather than revealing a black canvas.
- `_firstFrameReason` starts as `'boot-pending'`. Frames drawn before `App._openWorld` has applied the opening pose (`playOpeningShot`, `frameContent`, or a scenario's `camera.opening: false`) never report; `_openWorld` then calls `armFirstFrameSignal('boot')`, so the first frame the fade reveals is the opening pose. A return armed while the boot is still pending keeps the gate.
- The container `#characterMode` holds the frame's own colour underneath: before any renderer, the local-clock band (sky stops over that hour's sea for the lower 63 %, picked by an inline script in `index.html` before the first paint); on the boot first frame, the payload's four bands (`RevealBands.paintRevealBands`); on the switch to Dashboard, `captureFrameBands(8)` draws one frame and measures it into eight bands, held until the return's first frame.
- The bands read the frame through a 2D canvas (`_sampleFrameBands`), and the WebGPU HDR canvas (`rgba16float`) cannot be read that way: Chrome's copy of it into its BGRA8 raster image raises a validation error on the World's device. The World renderer therefore hands over `readoutSurface(96, 64)`, which is the canvas itself on SDR and P3 screens and, under HDR, the presented texture's nearest texels clamped into a small preferred-format canvas in the same colour space (`HDR_READOUT_WGSL`, the HDR display variant's `readout` pipeline). The bands under HDR match the SDR bands to 1–2 steps per channel.
- A resize (the activity panel opening or closing, a window or DPR change) keeps the screen-centre world point (`camera.holdCenter`, captured before the canvases change) and draws one frame synchronously through `renderNow()` inside the `ResizeObserver` callback, so the cleared backing store never reaches the screen and the centre never jumps out and back.

`VillageDirector` emits `village:director`, `village:building-signal`, `village:scene`, `village:replay`, and `village:camera-cue` as read-only presentation signals. Canvas overlays use the snapshot for huddles, handoffs, incidents, replay trails, release parades, building hover previews, and selected-building route lines; `CameraDirector` and the offscreen cue edges consume `village:camera-cue`; DOM surfaces such as Activity Panel may consume the same events defensively. A sub-agent return (`subagent:completed`) queues a neutral lower-third caption under a `RETURNED` eyebrow (`Review → Prime`, stone accent, no success wording); returns and biography banners never fire the gold release camera cue, the narrative-feed parade entry, or parade arcs, and `AgentBiographyService` does not count a sub-agent's removal as a completed session.

Deterministic QA scenarios for these states are available at `?sim=1&scenario=<id>`; the most relevant Director fixtures are `waiting-on-user`, `quota-rate-limit`, `failed-push`, `release-parade`, and `building-inspection-replay`.

## Adding a building

1. Add an entry to `BUILDING_DEFS` in `claudeville/src/config/buildings.js`. Copy a neighboring entry for the validated field shape:

   ```js
   {
     type: '<id>',
     x: <tileX>,
     y: <tileY>,
     width: <w>,
     height: <h>,
     label: '<UPPER CASE>',
     shortLabel: '<SHORT>',
     icon: '<glyph>',
     description: '<short>',
     district: '<district>',
     capacity: { work: <n>, ambient: <n>, overflow: <n> },
     visualTier: 'hero' | 'major' | 'minor',
     labelPriority: 'landmark' | 'standard' | 'low',
     entrance: { tileX: <tileX>, tileY: <tileY> },
     visitTiles: [workSlot(...), queueSlot(...), scenicSlot(...)],
     walkExclusion: [{ dx: <n>, dy: <n>, width: <n>, height: <n> }],
   }
   ```

   The local `workSlot`, `queueSlot`, and `scenicSlot` helpers create the visit-tile metadata expected by movement and occupancy systems. Tile coordinates must keep the footprint `(x..x+width-1, y..y+height-1)`, entrance, visit tiles, and walk exclusions within `0..MAP_SIZE-1` and not overlap water or another building footprint.

2. Add or reuse a `BuildingVisualRegistry.js` profile for label treatment, sprite IDs, decoration, emitters, lights, overlay anchors, and split-pass behavior. Keep procedural fallbacks in `BuildingSprite.js` narrow.

3. (Optional) If the building needs hover/click behavior beyond the default tooltip, subscribe in `IsometricRenderer.js` near the existing `_onMouseMoveMain` / `_onClick` handlers, or extend `BuildingSprite.hitTest`.

4. Run `npm run world:validate-buildings` and `npm run world:validate-terrain`, then reload the page. There is no build step; `App.js` adds buildings from `BUILDING_DEFS` on every boot.

Future building visual cleanup should expand the existing `BuildingVisualRegistry.js` coverage before adding custom procedural drawing. Good candidates are label accents/emblems, light sources, emitter specs, overlay anchors, and split-pass rules. Keep custom renderers behind named functions so adding a building usually changes config data rather than several distant `type` branches.

## Performance baselines and trail policy

**Resident quality ladder (plan 0.1, V2).** Display pacing is the ladder's authority in both directions; the GPU timer is only a veto that confirms the GPU is involved.

- *Latched period.* The loop hands the ladder each rAF timestamp gap (`IsometricRenderer._loop` → `gpuWorld.notePresentInterval`, on either resident backend). During the MINIMAL boot warm-up it takes p5 of 60 gaps (2–100 ms), snaps it to {60, 75, 90, 100, 120, 144, 165, 240} Hz and never re-derives it from achieved gaps, so a steady 60 fps on a 120 Hz panel still reads as missing. A screen or DPR change re-latches, `visibilitychange` clears the pacing window, and gaps above 4× the period are pauses, not misses. The veto budget is half the period (M26: 8.3 ms at 60 Hz, 4.2 ms at 120 Hz); `ladder.setBudgetMs()` replaces it until the next latch.
- *Demote.* One level, only when ≥ 20 % of the last 60 intervals exceed 1.5× the period **and** the median timing score (timer p25 plus upload, with the > 35 ms gap penalty) is over budget. Misses with a healthy timer are main-thread-bound (`missing:timer-under-budget`) and shed nothing. Without a timer (Safari, Firefox) the veto is waived.
- *Shedding didn't help.* The 60 intervals after a demotion must cut the miss share by a quarter; otherwise the step reverts and demotions hold for 60 s, doubling per repeat (cap 16 min). This ends the 3 ↔ 2 ↔ 1 ↔ 0 cycling.
- *Probe.* Above FULL, one level up once its backoff has elapsed (unless frames already miss with the timer over budget). The probe reverts as soon as its 60-interval window misses ≥ 5 % (baseline + 5 % when the lower level already missed) with the veto confirming, and is kept otherwise; failed probes back off 8 s, doubling to 64 s. Boot reaches FULL about 2 s after the latch at 60 Hz.
- *Return.* A Dashboard return resumes the last paced level at once (a pending probe's base level), keeping the latch and every backoff.
- *Timer.* The whole-frame GPU timer (WebGL2 a `TIME_ELAPSED` query, WebGPU a `timestamp-query` span through `GpuWgpuTimer`) is begun on 1 frame in 4 (every frame while ≥ 10 % of the window misses, so an overload confirms within 2 s); the ladder reads the p25 of the last 30 samples through the shared `selectGpuTimingMetrics`.
- *Light admission* is the `EFFECT_BUDGET` row `light-admission` (FULL 128, REDUCED 64, MINIMAL 24, attention lights first; binned into 64×64 tiles of ≤ 16, 2.4), so the night's pools ship at every level.
- *Receipts* follow the V2 rule in the `EFFECT_BUDGET` header: K8 slopes (`node scripts/smoke/world-fps-benchmark.mjs --mode=kslope`), the vsync-unlocked FULL-vs-MINIMAL delta (`--mode=unlocked`) and per-level real-frame throughput (`npm run world:gpu-burst`), on a quiet host. Ladder acceptance: `--mode=soak`, `--mode=inject` and `--mode=dashboard`. The debug GPU-side load is also reachable by hand: `?gpuLoad=<passes>` (drawn at FULL only, a load the ladder can shed; add `&gpuLoadLevels=all` for every level) or `renderer.gpuWorld.setDebugLoad({ passes, levels })`.

Persisted movement history is retained for diagnostics and replay but routine historical trails are not painted over the village. The selected agent and action-needed agents may draw only a short, bounded recent route. `TrailRenderer.getDiagnostics()` reports the active policy, confirms zero ambient cache ownership, and retains stationary/manual-pan/follow/director-glide timing buckets. Run `npm run world:benchmark-trails` after changing trails or camera invalidation.

Shift-D reports PostFX source upload, mask upload, setup CPU, shader CPU/GPU, ladder decision/degradation reason, named GPU resource bytes, mask rebuild causes, and trail camera-mode timing. On the resident GPU world it additionally prints the active quality level and reason; the pacing rows (latched rate and period, misses in the window, paced level, veto budget and verdict, any pending probe or step, cool-down and next-probe countdowns); the whole-frame timer p25 beside its raw EMA and sampling cadence; the shed list (`shed (reason): id mode, …` from `EFFECT_BUDGET`, whose key order is the shedding order), which names every active cap — `light-admission` with its admitted/offered counts, at FULL too whenever the FULL admission count (128) drops a light; per-pass GPU/CPU timings for `upload`, `scene`, `bloom`, and `present` once `renderer.gpuWorld.setPassSamplingEnabled(true)` starts the one-pass-every-12-frames rotation (`EXT_disjoint_timer_query_webgl2` on WebGL2, `timestamp-query` spans on WebGPU; disjoint samples discarded, unavailable never printed as zero; per-pass samples are not receipts on ANGLE-Metal); pinned versus evictable texture bytes with the live body-atlas size; and the agent-sheet row (B.2): equipped padded albedo sheets and their bytes against the 192 MB cap (48 M px), the pinned overage (on-screen profiles are never evicted, so bytes they hold above the cap print as `PINNED OVERAGE`), the released sheets with their retained LOD bytes, and the packed-geometry sheets. Only one backend's block is printed at a time so the inactive pipeline's zeroes cannot sit beside the active one's timings.

For World presentation changes, run `npm run verify:render` to capture deterministic screenshots and console evidence, then review the changed behavior on the operator-maintained server. Browser judgment remains manual; evidence capture does not.

## Frame and update notes

Astra carries Worldsplitter, her signature halberd, at every effort level. Effort reads through her distinct high-tier crests (the former effort floor rings and auras were removed with the other vector foot marks). Her armor and violet cape belong to the authored body and read strip; the halberd is composed separately through `AstraWeaponPose.js` with per-frame wrist coordinates. Read poses suppress equipment while both hands hold the book. Keep body, wrist profile, gauntlet palette, and portrait crop coherent when regenerating Astra.

- The render loop is plain `requestAnimationFrame`; one update tick per frame, no fixed timestep.
- Water shimmer advances from the shared visual elapsed clock and freezes when reduced motion is preferred. GPU water and wet-surface patterns use world coordinates, so camera movement does not drag the pattern across the surface.
- The terrain is baked into a `terrainCache` canvas by registered passes (`ground-splat`, `coast-field`, and the tile passes); only agents, effects, and weather redraw per frame. The bake key holds only what changes its pixels — cache bounds, asset availability, season, scenery revision, and each pass's revision — so a phase change or a zoom step reuses the cache; time of day and weather reach the ground and water through the grade and `waterMoodFor`. Adding terrain variation should register or extend a bake pass, not the per-frame path; call `invalidateTerrainBake()` when scenery changes. On the resident GPU path (B.2) the canvas lives only until the GPU holds its upload (`gpuWorld.hasResidentTexture`): `releaseTerrainCanvas()` drops the backing store and a same-size `gpuResident` stand-in keys the terrain record; a lost context, an evicted texture or the Canvas path re-bakes it once (`_getTerrainCache()` without `allowResident`).
- The terrain canvas is kept while a WebGPU switch is compiling or armed (`_pendingWebGpu`, `_worldSwap`): the incoming world starts without the texture and uploads the kept canvas in the swap frame instead of re-baking it there (a 340–510 ms bake measured in the swap frame before, a 42–66 ms swap frame after, on a loaded host); the first frame after the swap releases it.
- Equipped Codex sheets on the resident path (B.2): an albedo that only crowd (0.5x LOD) bodies sample is released 3 s after its last 1:1 use and its cache entry keeps the LOD sheet; a 1:1 body that needs it again recomposes it (same pixels) at most one compose per animation frame — inline for a selected, hovered or action-needed body, otherwise from the derived-art queue — and samples the LOD sheet at its own 1:1 size (each LOD texel two world texels) until its turn, so it never changes size. Composed, LOD and packed-geometry sheets, the agent atlases and dashboard avatars are CPU-backed (`willReadFrequently`) so Chrome keeps no GPU copy of the CPU sheets they draw (80-150 MB less GPU-process memory at dense-100 1080p). Cost: agent-atlas slot and walk-strip patches upload from CPU memory on the main thread, +0.18 ms/frame at dense-24 2560x1440 with 17 strips (noted beside `EFFECT_BUDGET`); B.1b/B.3 CPU cuts should count it.
- Event-bus subscriptions (`agent:added`, `agent:updated`, `agent:removed`) are stored in `_unsubscribers` and torn down in `hide()`. New subscriptions in this directory should follow the same pattern to avoid leaks across mode toggles.
- `ParticleSystem.setMotionEnabled(false)` is set when `(prefers-reduced-motion: reduce)` matches; respect this when adding new effects.
- New motion-bearing features must follow [`../../../../docs/motion-budget.md`](../../../../docs/motion-budget.md): check `motionScale` before allocating animation resources, declare a pulse band, and ship a static reduced-motion fallback.
- Use `PulsePolicy.js` helpers such as `pulseValue()` and `pulseAlpha()` before adding another repeating sine cadence. Local pulse math should be justified by a feature-specific need and still honor reduced-motion fallback values.
