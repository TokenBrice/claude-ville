# World Mode Renderer

World mode is the resident WebGL2 isometric view that ClaudeVille shows by default, with Canvas 2D fallback. This directory owns the render loop, sprites, camera, and particles. It reads from the domain `World` and listens to the event bus; it never mutates domain state.

The directory is named `character-mode/` for historical reasons. In prose, the user-facing surface is "World mode" (paired with "Dashboard mode" under `../dashboard-mode/`).

## Data sources and draw order

World mode is driven by four source layers:

- Domain state from `World` (`agents` and `buildings`).
- Static config from `src/config/constants.js`, `buildings.js`, `townPlan.js`, `scenery.js`, and `theme.js`.
- Sprite metadata from `claudeville/assets/sprites/manifest.yaml` and `palettes.yaml`.
- Runtime provider state already normalized into `Agent` objects, including `gitEvents` for harbor activity.

The frame (`WorldFrameRenderer.renderWorldFrame`) draws in broad layers:

1. Backdrop on the 2D canvas: the stepped sky plate, painted in final C2 colours on WebGL (where `BackdropGrade` lays the scene's vignette courses and aerial haze over it) and in its preimage (`ungradeRgb`) on Canvas, whose frame grade then lands it on the same colours. On Canvas the backdrop also carries the open sea (`drawOuterOcean`, preimage, world-anchored fills); on WebGL the composite paints the sea (5.).
2. The terrain cache: the `ground-splat` bake and its far-row haze, then the `coast` stage (baked water ramp per world texel, foam lace, outer shelf, the SW/SE shoreline mass; painted after the haze so every water, foam and wet-sand texel is an exact CoastBake colour), bridges, foundations, flat features, then the `finish` stage (3.7 static reflections over all of them, then the resident water fields). It carries no time of day. On Canvas (3.12) the terrain pass then draws, in world space: the water mood copy (`drawCanvasWaterMood`), `CanvasWaterState`'s step overlay (reflection ripple, caustics or the static dashes, near-shore / river current and deep swell crests on in-map water and the open sea, specks, rain rings, swash), the Lighthouse sheen, the sun/moon path, then the stepped lamp columns (`_drawBuildingLightReflections`); the WebGL scene and composite shade the same rules per fragment.
3. Ground records: live ground cues, building and tree casts, and villager contact shadows and rings.
4. The depth-sorted pass: props, building bases and occlusion-aware hero pieces, agents, landmark activity, building fronts, and every world particle at its spawn sortY. On the resident path the overlay-safe scene categories (Harbor traffic with wildlife, landmark activity, bridge lanterns) are skipped here and drawn once on the overlay. A body whose feet fall between a split building's back and front depths, behind its footprint, sorts before the back half so the whole building hides it. On WebGL the records are V9 instances (`docs/material-channel-contract.md`): opaque sprite records write a DEPTH_COMPONENT16 painter depth (`depthFunc ALWAYS`, so painter order still decides colour), then the particles draw once with LEQUAL and no depth write, so a particle behind a nearer building front or body is hidden.
5. The grade: on WebGL the scene pass grades each albedo fragment with C2 before the light loop, adds the stepped multiplicative pools and authored emission after it, and shades each record's world-locked cloud courses and screen-Y aerial haze on its own texel grid; the composite then paints the open sea (3.3/3.4) under every scene.a < 1 pixel below the horizon with the in-map water's own pipeline (stop, crests, path, mood, cast, grade, cap, sky courses, vignette, fog, cloud courses, cat's paws, squall), adds the Lighthouse beam over sky and sea, the flash and bloom. The Canvas fallback reproduces the same grade with composite fills (`CanvasGrade`); the hybrid PostFx pass grades the finished 2D frame, lays its pools through the V5 receiver mask and blooms only the emitter cuts' own emission (the 2.9 water columns and the cuts land on the overlay just before this pass, which reads their emission).
6. The ungraded upper overlay, in order: weather foreground; reduced-motion chimney wisps and functional building marks (WebGL only); talk arcs; crowd `+N` tabs; arrival, comet, crown, and bracket moments; Director overlays (ground rings only for the selected building and incidents, as static 1-texel pixel outlines; no team, lifecycle, or per-building signal halos); overlay-safe scene categories on WebGL, or fireflies on Canvas; the selection chevron re-strike; per-agent overlays and names; the selected x-ray; the shared-file plate; T3 plaques (which treat the lower-third caption strip as occupied); the Harbor summary; the work score; offscreen cue edges; the neutral brass letterbox (no glide grade: nothing tints the frame); T1 attention plates; the lower-third caption; debug.

World mode renders through a three-canvas stack inside `#characterMode`: `#worldCanvas` (the 2D scene, source of truth and mouse target), `#worldFxCanvas` (WebGL2 output, hidden whenever inactive), and `#worldOverlayCanvas` (2D UI: weather foreground, marks, labels, moments, letterbox, debug — never graded or distorted). The canvases stay at opacity 0 until the renderer emits `world:first-frame`, then fade in (360 ms on boot, 220 ms back from Dashboard, no fade under reduced motion) over the container's stepped bands (see the boot and first-frame contract under Event-bus integration). Grading ownership is exclusive: when a GPU stage is active the 2D grade and pool stamps are skipped and the GPU grades from the same C2 `lightGrade`; when inactive (`?postfx=0`, no WebGL2, context loss, or ladder level 3) the Canvas fallback grades the finished frame itself. Shift-D shows post-FX level and timings. Resident WebGL replays only functional building marks and occupancy pennants on the upper Canvas in drawable depth order; authored manifest layers and atmospheric building reactions remain owned by the GPU path.

**Renderer selection.** `show()` picks the World backend once per page. `?renderer=canvas` gives the Canvas world (with the hybrid PostFx), `?renderer=webgl` forces the resident WebGL2 world wherever WebGL2 exists, and `?postfx=0` gives the Canvas world with no WebGL layer. With no flag (an empty or unknown `?renderer=` value counts as none: only exactly `webgl` or `canvas`, any case, skips the probe; `GpuWorldPolicy.forcedGpuWorldRendererMode`), the resident WebGL2 world runs on a hardware rasterizer and the Canvas world on a software one. `GpuWorldRenderer.probeWebgl2Raster()` probes throwaway canvases and treats the rasterizer as software when the browser refuses a `failIfMajorPerformanceCaveat` context or the unmasked renderer string names SwiftShader, llvmpipe, softpipe, lavapipe or the Microsoft Basic Render Driver (`GpuWorldPolicy.isSoftwareRasterizer`). The resident scene and composite programs are uber-shaders. A software rasterizer pays for every branch of them, so on headless Chromium's SwiftShader the first frame JITs for about 3 s and each frame then costs about 200 ms of GPU time, with the main thread blocked on every frame's readback. The Canvas world draws the same scene there at about 50–70 ms a frame. `renderer.worldRendererMode` reports the choice. Plain headless Chromium (`npm run verify:render` and the other smokes) therefore captures the Canvas world. Tools that need the resident path launch with `GPU_LAUNCH_ARGS` (`scripts/smoke/support/world-bench.mjs`) or pass `?renderer=webgl`.

Ground semantic cues (Director routes/replay/halos, relationship rings/tethers, crowd auras, and short selected/action routes) share one set of ground painters. Canvas paints them all into the frame. The resident path splits them by how they change: cues that follow an agent or pulse (incidents, council rings, tethers, trails, the hovered or selected building's routes, the shared-file knot) are recorded each frame by `GroundCueRecorder` as native ground records on the art-pixel grid, so moving agents move records and never re-upload texels; tile-anchored crowd auras and transient or text-bearing washes (recoveries, the parade, replay, the work score) stay in one retained Canvas texture drawn at scale 1 or exactly 0.5 (`semanticGroundScale`) that re-renders only when their quantized state changes, plus an 8 Hz tick while a transient animates. Buildings and bodies occlude both. **Dot runs (B.3):** council rings and tethers are texel-dot curves, so the recorder joins consecutive same-paint dots (at most 4×4 texels, up to 15 per run, each step within a 4-texel window of the run's smallest) into one record flagged V9 `cueRun`, whose loc1 carries the packed integer steps instead of UVs; a cue batch holding runs draws six vertices per dot and the vertex stage (`CUE_RUN_GLSL`) rebuilds each dot's own rect on its swatch texel in call order, so rasterization, blending and pixels are those of the per-dot records (hash-identical at fixed poses against the per-dot recorder). Dense-100 at the overview holds about 60–70 cue records instead of about 950 dots. Talk arcs, counts, handoffs, lifecycle annotations, and selected x-ray silhouettes draw once on the upper Canvas in all backends.

Canvas, GPU, and camera hit projections share backing-pixel-snapped translation while logical pan and zoom stay continuous. Every world sprite draws at an integer multiple of the world texel (contract C3): villagers and trees at 1×, effects and glyphs on the art-pixel grid. Harbor hulls, `prop.flowerCart` and held Codex weapons are no exception (3.8): hulls are 5-frame roll strips baked at scale 1 (`scripts/sprites/bake-harbor-hulls.mjs`, cleanEdge, 1-px waterline lip) drawn as `harbor-hulls` scene-category V9 records (`HarborHulls.hullRecords`: a `ground:wake:*` V-wake stamp, a `ground:reflect:hull:*` twin carrying the V9 `reflect` flag, which the vertex stage mirrors about its base and the scene fragment keeps on painted water only, and the timber `harbor:hull:*` record, a receiver with a vertical axis (`frontCornerX` = the waterline pivot, `footY` = the waterline, V9 flag `receiverAxis`) so a lamp beside a hull lights its lamp side; a hull behind a split building sorts before its back half, `behindSplitBuildings`, and its flags and plates drop only while that building's silhouette covers its masthead or most of the hull, `HarborTraffic._marksHiddenBehindBuilding`). Hull timber sits at the Harbor's value (`bake-harbor-hulls.mjs normalize`: the upright frame's warm-texel mean lands on 60 luma through whole-stop sun-key courses), and every ship flag hoists at the hull's masthead (manifest `masthead`, turned with the roll frame; `HarborTraffic._flagAnchor`), the cart draws at 1×, and weapons are cleanEdge frames baked once per (source, flip, scale, angle) at one pixel per world texel (`WeaponFrames.js`). `npm run sprites:validate` fails on any `ctx.rotate` or non-1 `ctx.scale` in ship or weapon drawing (`scripts/sprites/texel-transform-check.mjs`; only the screen-fixed plate cancel `scale(1 / zoom, 1 / zoom)` is allowed). 3.11: bodies whose feet are within 0.3 tiles of the waterline, or stand within 16 world px above open water (a pier or quay edge), get the same albedo-only reflect twin (`WaterReflections.js`, at most 12 nearest the camera centre, FULL only). Under crowd pressure ordinary GPU bodies sample the baked 0.5× crowd LOD sheet at world scale 1 and skip the 1:1-sized stance and ritual gestures; selected, hovered, waiting, errored, and rate-limited agents keep full silhouettes. Labels follow the C5 tiers: T1 attention plates always, T2 plates for the selected and hovered agents, T3 district plaques, T4 routine names only at zoom ≥ 1.6 for the top three (six at zoom 3) most recent actors per 200 px screen region, dropped rather than offset on overlap, and the T5 `+N` tab for the unnamed rest of a dense group. An agent whose arrival is pending stays unnamed. T2 and T4 labels sit below the body's ground marks; a T4 name that would cross another body is dropped; a T2 plate is shifted wholly inside the canvas while any part of its body is visible and dropped when the body is entirely off-canvas (the T1 edge plate still names it). A body hidden behind a building draws no name, action marks, or bubbles unless it is selected, when it keeps the x-ray and its plate. The signature clasp shows only at zoom ≥ 3 or on the selected body. Automatic establishing and idle focus moves never rest above tier 1; explicit detail zoom remains available, and selection through the Sidebar, Dashboard, or keyboard agent cycling reveals an individual immediately.

Foliage draws oak, pine, and willow sprites at 1× from at most six cached canvases; their baked plinths were stripped offline (`scripts/sprites/foliage-pass.mjs`), and trees stand in clumps rather than a sprinkle. The material pilot uses exact palette overrides only for Terra, Sonnet, and Command; albedo and emission stay unchanged. Command's re-authored sidecars classify fire, glass, timber, crimson cloth, metal, and stone from reviewed colours, never from brightness. This is a small authored pilot, not a roster rollout.

Agent atlas slots normally refresh at 125 ms. A measured fast-turn sequence exposed a stale selected Codex body while attachments advanced; selected, hovered, action-needed, direction-changing, and tool-changing slots now refresh immediately. Other dirty animation slots retain the ambient cadence. **Walk strips (4.7):** an on-screen, non-LOD walker's record carries `walkStrip` (`AgentGpuOverlayRenderer`: six probe records, one per walk frame of its facing, each resolved by `setFrameRecord` itself so padding and every channel source match; rebuilt only when direction, tool, sheet or asset version move, or a pending channel crop lands). `packGpuAgentFrameAtlas` gives such a body a six-cell strip in a band below the slot grid (atlas `max(columns, 6) × cell` wide, `rows + stripRows` cells tall; albedo and channel atlases share the geometry) and each frame samples `stripX + frame × cell`, so the drawn pose changes on every walk frame. A strip cell is copied and uploaded (`texSubImage2D`, one cell per channel) the first time its frame shows and refills only when the strip key moves; the band grows in quanta of 4 strips, capped at 24 and at 2 M px per atlas (17 strips at the 140 px equipped cell), holders keep their strip, and past capacity urgent walkers and those nearest the view's middle win while the rest keep the slot cadence. Idle, posed (action strip) and crowd-LOD bodies keep single slots. GPU surface animation and foliage consume the public `motionTimeMs` visual clock. Existing zero-height character geometry masks remain flat; the renderer now honors their authored value instead of manufacturing anatomical height from a default floor.

**Living water (Waking Isle 3.1, 3.2, 3.6, 3.9, 3.10).** Every water motion on the resident path is palette cycling in `SCENE_FRAGMENT` on the ungraded albedo, never a multiply or a crossfade: a texel is a depth stop only by exact match against `COAST_PALETTE.stops` (CoastBake), so reflections, dither blends and fat-pixel mixes never cycle, and a lit texel only ever takes another named colour (the next shallower stop, `FOAM_CREST`, `FOAM`, a seabed speck, a caustic half step, or a C1 `seaPath` stop). The coast bake publishes two lattice fields (`renderer._coastBake.waterFields`, one texel per 2×2 world-px coast cell, origin `x/y`, `cols × rows` 1536 × 768), uploaded once per coast bake through the V9 typed path: unit 7 `u_cycleOffset` (R8: 0–15 shoreward swell band, 16–31 river current band along the authored river axes, 255 none) and unit 8 `u_coastField` (RG8: R = `round(sd·64) + 128` in tiles, sd > 0 water; G bits 1 reflection cell, 2 swash-eligible, 4 painted water, 8 wet sand), addressed by `u_coastRect = (x0, y0, cols, rows)` (z = 0 when absent, at MINIMAL). GLSL helpers for other readers (3.7 ripple, 3.11 reflections): `coastFieldAt`, `waterStopIndex`, `waterStopForSd`. `SEA_SWELL_GLSL` (`deepSwellLit`, `glintDash`, `seaPathCap`) is uniform-free so the open ocean in the composite lights the same crests and path; `u_glint = (screenX, strength, kind, grow)` and the active pair of `seaPath` stops are resolved once per frame (`GpuWorldRenderer._glint`, `_glintStops`). One water clock, `u_waterFx.x` (the motion scale, 0 under reduced motion and at MINIMAL): the crests freeze on today's static dash frame, the path on a static speck set, rain on a fixed 20 % ring set; the swash and the caustic net stop. Budgets and bands: `docs/motion-budget.md`.

When adding a visual feature, place it in the lowest layer that still communicates the state. Avoid adding per-frame work when it can be cached into terrain or static scenery.

## Depth drawable contract

World mode overlap rendering goes through `DrawablePass.js`. New overlap-aware visual systems should adapt their items to this shape before entering the shared sorted pass:

```js
{
  kind: '<stable-category>',
  sortY: <finite-world-y>,
  sortBand: <optional-order-band>,
  stableKey: '<optional-deterministic-key>',
  salience: 'primary' | 'recent' | 'working' | 'ambient',
  materialId: '<stable-material-source>',
  materialClass: '<known-class>',
  elevation: { base: 0, top: 0, unit: 'sprite-px' },
  emissive: { strength: 0, sources: [] },
  occluder: { mode: 'alpha-silhouette', strength: 1 },
  atlasFrame: null,
  drawFallback(ctx, zoom, context) {},
  buildGpuRecord(context) {},
  hitArea: null, // optional future hit-test metadata
  payload: <source-object>
}
```

`kind` should be stable enough for diagnostics and narrow special cases such as the selected-agent x-ray pass. Ordering is `sortY`, then `sortBand`, then `kind`, then `stableKey`, then insertion sequence. `createDepthDrawable()` assigns default bands for building backs, props, harbor traffic, agents, landmark activity, chronicle monuments, familiar motes, and building fronts (the Chronicler has no kind: its Canvas-only body was removed in Phase 3); set `sortBand` only when a new category needs deterministic interleaving. Normalize missing or non-finite `sortY` before sorting. The legacy `draw()` property remains an alias of `drawFallback()`, so Canvas output is unchanged. `buildGpuRecordsFromDrawables()` converts the already-sorted stream and adds `drawOrder`; consumers may batch only consecutive compatible records. Avoid adding new manual draw switches in `WorldFrameRenderer.js` when an adapter in `DrawablePass.js` can preserve the existing behavior. Use `cullDepthSortedDrawables()` for large drawable sets that can be skipped outside the camera viewport.

Static props (`StaticPropSprite` in `StaticPropDrawables.js`: trees, boulders, district props, walls, the Village Gate) sort at their footprint world Y unless they pass an explicit finite `sortY`. A tall prop may `splitForOcclusion` into back and front halves so a villager can stand between them. A prop that is long along one tile axis cannot use one depth: the ends of the 9-tile gatehouse sit about 140 world px apart. Such a prop passes `occlusionColumns` from `lineOcclusionColumns()` instead. These are vertical slices of one cached image (16 px wide for the gate), and each slice sorts at the wall line's Y under its centre, so anything north of the wall paints first and anything south paints after. Both backends cut the slices with `columnSourceSpan()`. A column prop always draws from its cache, so a drawn-state change such as the gate doors must call `invalidateCache()`.

Material metadata is optional. Missing values normalize to unlit albedo, zero emissive contribution, a flat alpha-silhouette occluder, and no atlas frame. See [`../../../../docs/material-channel-contract.md`](../../../../docs/material-channel-contract.md) for manifest fields, stable material indices, atlas frame tags, channel encoding, and tooling.

`WorldFrameRenderer.js` still reaches into renderer private helpers for terrain, atmosphere, debug, labels, and post-processing. Treat that as a follow-up for layer extraction, not a reason to broaden a drawable-only change.

## Selection lifecycle

```
canvas click (IsometricRenderer._onClick)
  → camera.screenToWorld(x, y)
  → IsometricRenderer._handleClick(worldX, worldY)
      hit-test agentSprites, front-most first (gate departures skipped)
      ├── agent hit → sprite.selected = true
      │               camera.followAgent(sprite)
      │               onAgentSelect(agent) → App.js emits 'agent:selected'
      │
      ├── building instrument hit (Forge result tile, task-board plan tab)
      │             → selects that session through the same path
      │
      ├── monument hit → opens its stone ledger; onAgentSelect(null)
      │
      └── miss → camera.stopFollow()
                 onAgentSelect(null) → App.js emits 'agent:deselected'
                 then emits 'building:selected' for a building hit,
                 otherwise 'building:deselected'

eventBus 'agent:selected' (also emitted from Sidebar / DashboardRenderer / ActivityPanel)
  → App.js _bindAgentFollow → renderer.selectAgentById(agent.id)
  → ActivityPanel.show(agent) (the panel module and stylesheet load on the
    first selection), starts 2s detail polling

eventBus 'agent:deselected' (World miss, ActivityPanel close, Escape,
or 'agent:removed' for the current agent)
  → App.js → renderer.selectAgentById(null) → camera.stopFollow()
  → ActivityPanel closes
```

`onAgentSelect` is wired in `App.js` after the renderer is created and routes through `shared/AgentSelection.js` (`emitAgentSelected`, `emitAgentDeselected`). The renderer keeps a single `selectedAgent` reference; clearing it deselects every sprite and stops camera follow.

## Event-bus integration

`IsometricRenderer.show()` subscribes to domain events and stashes the unsubscribe functions in `_unsubscribers` for teardown:

| Event | Effect on the renderer |
| --- | --- |
| `agent:added` | `_addAgentSprite(agent)` creates an `AgentSprite` and starts its arrival. |
| `agent:updated` | Applies the update to the sprite; a departed agent starts walking out, a session that returns mid-exit turns around at the gate, and one that returns after leaving arrives again. |
| `agent:removed` | Starts the departure for a sprite that has not already left. |
| `subagent:dispatched` | Queues the summon ritual. |
| `building:active-agents`, `building:selected`, `building:deselected` | Caches building presence tiers for emitter gating and invalidates the idle frame. |
| `camera:auto-camera` | Toggles the Auto camera. |
| `biography:updated` | Applies earned nicknames to name tags. |

While Dashboard mode is active, the agent handlers skip arrivals and departures and mark sprite state dirty; it is reconciled when World mode returns. Selection events (`agent:selected`, `agent:deselected`) are bridged in `App.js`, not subscribed here directly. The renderer exposes `selectAgentById(id)` for that bridge to call.

`mode:changed` is consumed by `IsometricRenderer` to call `setWorldModeActive(mode !== 'dashboard')`. When Dashboard mode is active, the World render loop stops and volatile renderer caches are released; when World mode becomes active again, dirty sprite state is reconciled and the loop restarts. Browser visibility and canvas context loss/restoration also pause, resume, and rebuild canvas-owned caches. `App.js` captures the camera pose on the switch to Dashboard and restores it with `camera.resumeViewPose` on return instead of re-framing. `ModeManager` switches modes as a cut inside one task (show the incoming surface, hide the outgoing one, emit `mode:changed`), so the Dashboard lays out and the World measures its last frame before the browser paints; there is no mode fade.

**Boot and first-frame contract (0.3).** The World never presents a black, stale-pose or pale frame:

- `world:first-frame` fires once per activation (`reason` `'boot'` or `'return'`) from `_signalFirstFrame`, right after a render in the same task, with `{ reason, sky, sea, horizonY, bands, cell }`: `sky` is the live sky palette, `horizonY` the sea horizon's screen fraction (0 when it is at or above the top edge), `bands` four `{ top, color }` stepped bands measured from that presented frame (seamed on the horizon when it is on screen), `sea` the frame's mean colour below the horizon, and `cell` the art texel in CSS px. There is no timer fallback: a renderer that never draws keeps the world hidden rather than revealing a black canvas.
- `_firstFrameReason` starts as `'boot-pending'`. Frames drawn before `App._openWorld` has applied the opening pose (`playOpeningShot`, `frameContent`, or a scenario's `camera.opening: false`) never report; `_openWorld` then calls `armFirstFrameSignal('boot')`, so the first frame the fade reveals is the opening pose. A return armed while the boot is still pending keeps the gate.
- The container `#characterMode` holds the frame's own colour underneath: before any renderer, the local-clock band (sky stops over that hour's sea for the lower 63 %, picked by an inline script in `index.html` before the first paint); on the boot first frame, the payload's four bands (`RevealBands.paintRevealBands`); on the switch to Dashboard, `captureFrameBands(8)` draws one frame and measures it into eight bands, held until the return's first frame.
- A resize (the activity panel opening or closing, a window or DPR change) keeps the screen-centre world point (`camera.holdCenter`, captured before the canvases change) and draws one frame synchronously through `renderNow()` inside the `ResizeObserver` callback, so the cleared backing store never reaches the screen and the centre never jumps out and back.

`VillageDirector` emits `village:director`, `village:building-signal`, `village:scene`, `village:replay`, and `village:camera-cue` as read-only presentation signals. Canvas overlays use the snapshot for huddles, handoffs, incidents, replay trails, release parades, building hover previews, and selected-building route lines; `CameraDirector` and the offscreen cue edges consume `village:camera-cue`; DOM surfaces such as Activity Panel may consume the same events defensively. A sub-agent return (`subagent:completed`) queues a neutral lower-third caption under a `RETURNED` eyebrow (`Review → Prime`, stone accent, no success wording); returns and biography banners never fire the gold release camera cue, the narrative-feed parade entry, or parade arcs, and `AgentBiographyService` does not count a sub-agent's removal as a completed session.

Deterministic QA scenarios for these states are available at `?sim=1&scenario=<id>`; the most relevant Director fixtures are `waiting-on-user`, `quota-rate-limit`, `failed-push`, `release-parade`, and `building-inspection-replay`.

## Operator controls and cross-surface contracts

Four explicit controls own the frontier instruments. None is on a timer, and each leaves the default frame exactly as it found it:

- **READ (hold `B` or the World dock's READ button)** — while held, occupied-building plaques show work verbs translated from the canonical tool classifier (`FORGE` reads `WRITING · 8`), non-primary agents show their verb instead of routine names, and releasing restores names without changing selection (`IsometricRenderer.setReadMode`, `BuildingSprite.READ_VERBS`).
- **`A` attention frame** — frames the complete action-needed set ranked by real `awaitingSince` through `AttentionFraming.fitAttentionFrame`; when geometry cannot include everyone, the overlay states the exact excluded count instead of silently omitting agents, and each agent outside the view keeps an edge attention plate. After the glide lands the frame holds for up to 12 s: it soft-follows the included bodies and plates, each walking body's box extended to where its path ends (`softFollowWorldBox`, pans preferred, never zooming in, owner `user`), and ends once every one has stood still for 1.5 s, at 12 s, or on any genuine input, selection, `F`, Ambient or replay (a wheel or drag ends it before the next frame). A body the frame can no longer hold moves to the excluded count. Reduced motion re-cuts once, when the set settles. Entering focus also quiets the room: ordinary speech rectangles and duplicate routine names yield while the chosen agent's body, name, reason, and every unresolved primary mark stay.
- **FREE | AUTO | AMBIENT (the World dock, 9.1 / 4.4)** — one segmented control for who moves the camera, one segment pressed at a time (`App._initCameraModeControl`). FREE and AUTO are the persisted Auto-camera preference (`cv-auto-camera`, `camera:auto-camera`, also SET's Auto camera row). AMBIENT is the only way into Ambient ownership (C6): a wide shot of the active districts at the wide shot scale (z2 on the 5120 × 1440 ultrawide, z1 at 1920 and on the DPR-2 laptop), patient lateral glides on the ambient curve family to the busiest real work cohort at the medium scale (z3 on the ultrawide, z2 at 1920 and at DPR 2), an earned incident chapter with its own held letterbox, and a return to the wide, with factual lower-third captions (`Forge · 4 working`) and 20–30 s holds. Any genuine input revokes the claim; AMBIENT then wears its resume pip (a hollow gold square) and waits to be asked again, and nothing re-arms on a timer; Auto's timers are untouched. Choosing AMBIENT is a standing choice (`cv-ambient-standing`, M8): it is reclaimed after the boot opening glide has settled (unless the operator already moved the camera, which shows the resume pip instead) and on `world:first-frame` with reason `return`; a Dashboard trip drops the claim but keeps the choice; only FREE or AUTO clears it. Reduced motion holds one static overview at the wide scale with the same counts.
- **SCORE (Activity Panel)** — draws the selected run's last 20 minutes as the spatial work score with a scrub cursor and one playback pass over the kept span; reduced motion keeps the static diagram and never allocates the playback timer.

Camera behaviour the operator sees (`Camera.js`, `CameraCurves.js`):

- **Shot scales (4.1).** Automatic framing picks shots by the world area the canvas shows, not by tier index: `shotScaleTiers(viewportW, viewportH, ladder)` returns the survey (the largest logical tier showing ≥ 95 % of the island diamond, else none) and the logical tier ≥ 1 log-nearest 1.4e6 (wide), 0.55e6 (medium) and 0.2e6 (close) world px². Recomputed on every viewport size change: 1920 × 1080 DPR 1 has no survey and wide/medium/close 1/2/3; 5120 × 1440 DPR 1 surveys at z1 with wide 2 and medium 3; 2560 × 1440 DPR 1 surveys at z1 with wide and medium both 2; 1512 × 982 DPR 2 surveys at 0.5 with wide 1 and medium 2. DPR-2 half rungs are never shot scales. Settled: at DPR 2 the Ambient wide rests at z1 (the resolved table's wide), not at the 0.5 survey it held before 4.1; the survey remains the opening's first frame only.
- **Land-weighted composition (4.2).** Automatic owners (`system`, `director`, `idle-auto`, cues, Ambient, the tour) never rest on more than 30 % sea when the subject allows it: the centre steps 16 world px at a time toward the island centroid until the sea share of the frame (measured analytically against `mapWorldCorners`) is ≤ 0.30 or the subject box would enter a 12 % inner margin. The establishing shots, the opening's settle on live content and the Ambient wide (`keepLandmarks`), then keep landmark tops whole. The camera derives building silhouettes from `camera.setSpriteMetrics`, which the renderer feeds with asset dims, anchors and alpha masks. It then moves the pose on the 16 px grid, at the same zoom, to the offset that crops least: first the smallest summed crown overshoot above the top edge (or above a reserved chrome rect in the crown's columns, `shared/ReservedRects.js`, e.g. the World dock), then the smallest plate overshoot (the plate drawn 24 px over the crown), then the shortest move. Villagers never give way: no subject edge moves into the 12 % margin or deeper into it, no villager the shot shows whole (the wide passes the live bodies as `bodies`) leaves the frame, and sea never exceeds max(0.30, the pose's own). At 5120 × 1440 the z2 wide cannot keep the Archive's crown, the Lighthouse's crown and the south villagers all in frame under 0.30 sea, so the residue is the smallest crop the villagers allow. An Ambient cohort shot frames only the members at the building (folded on its footprint or visit tiles, or within its long side plus three tiles of its centre), published as `subjectIds`; a member chatting at another building is not in the shot. Operator poses, follow, the `A` hold and manual pan are untouched.
- **Opening.** Boot fades in on the whole island at the survey shot (the wide where the viewport has none: z1 at 1920), holds 1600 ms at rest, then one 2400 ms continuous dolly (`OPENING_DOLLY_MS`, 4.6; stepped on Canvas, see *Glides*) settles on the content at the medium scale at most (z3 on the ultrawide, z2 at 1920 and at DPR 2). Where the island leaves vertical slack, the survey (and the tour's island stop) puts the sea horizon at 11 % of the world viewport (10–12 %) so the sun or moon disc stands whole above it, with at least 4 % under the island (4.5); the horizon appears in no other automatic shot (M8). Scenarios with a camera pose play the opening and settle on that pose unless their metadata sets `camera.opening: false`; `setCameraPose` cancels any glide in flight, so capture tools are never overwritten. Reduced motion cuts.
- **Glides and wheel.** The wheel is a 150 ms easeOutCubic step in log space through every resting rung (at backing DPR 2: 0.5, 1, 1.5, 2, 2.5, 3; texel runs are exactly k = 2·zoom backing px). Director moves (cues, attention, re-frames, returns) use easeInOutCubic and Ambient/tour moves easeInOutSine, with duration `clamp(600 + 0.55·screenPx + 350·|log2 z1/z0|, 700, 2400)` ms on the dolly's own screen travel (Ambient ×2.2, capped at 5 s). Every glide is one continuous dolly (4.6, M4): centre and log-zoom move together on the family curve, a push-in covering its ground while still wide and a pull-out opening before it travels, with no plateau between pan and zoom; it lands exactly on its target's resting tier, snapped to a whole backing pixel so the landing frame is the nearest frame with no settling nudge. The Canvas world has no fat flight frames, so there (`Camera.fatFlight` false: set every frame by `WorldFrameRenderer` from the live world renderer) the same glide is planned stepped (`planGlide(…, { rungs })`): the same duration, but the zoom rests on the logical rung (survey, 1, 2, 3; never a half rung) log-nearest the dolly's zoom and changes rung in one easeInOutCubic step centred where the dolly crosses the log midpoint of the two rungs, each step a quarter of the glide shared among its rungs and held to 150–450 ms, so ≥ 75 % of the frames sit at an integer k. The centre follows the zoom shown: the tighter frame's centre (a push-in's target, a pull-out's start) keeps the continuous dolly's screen path exactly, so both frames' centres cross the screen one way and nothing backs up while a rung step scales the picture. Caption priority is incident > verified release > returned > milestone (`captionSource` in `WorldFrameRenderer`): an incident is Ambient's chapter or a verified failed/rejected push inside the 25 s window; the standing Ambient line sits below RETURNED and above a milestone; `VillageDirector` stages a pending RETURNED line before any biography banner and pre-empts one already up (it returns to the head of the queue), so a biography banner never blocks the first three.

**8.3 moments peak on the score's notes**: `createCueGate(kind, key)` + `cueGatedAge(gate, age, peakAt, residueAt)` (EffectStamps) hold a moment's clock on the frame before its peak until its carrying note is due, and before its residue until the cue's last note is due. The carrying note is the cue's first note the moment can still reach without cutting its anticipation below the 120 ms floor (a note already sounding pulls the peak in by at most 80 ms): usually note 0. A body-led moment declares its peak first (`scheduleAccent`, `CUE_ACCENT_NOTE`) so its note is scheduled onto it: the release crown, which starts once its sloop has revealed at the slip about 600 ms after the plant, declares its cream frame (one frame late, keyed by the record's agent as the peal is) in the plant's own task, so the peal's first note lands on it. The muted route anchors the same way: a release voiced announce-only (the Signals preset) publishes its silent score with note 0 on the declared frame, not at admission, so the crown still peaks on note 0. No moment waits more than 1.5 s in total (`CUE_MAX_HOLD_MS`). Kinds: the arrival beat `arrival` (agent id), the dispatch impact `dispatch` and the merge impact `subagentReturn` (parent id), the release crown `release` (any key), the failure bracket `pushFailed` (the pushing agent: `harbor:updated` rows carry `agentId` and `latestFailureAt`, and include a repo whose failed push has nothing docked; the first summary a page sees counts a failure younger than 15 s as news). While the Town band sounds, only an aggregated outcome declares `expectCueScore` (its score is published when its batch closes); a dispatch/return batch closes 560 ms after its last fact (`MOMENT_AGGREGATE_MS`, at most 1.5 s after its first), so its note sounds inside the last comet's pull window or just after its impact and the comet barely waits; an outcome emitted at once scores inside `submit`. With no admitted score `cueNoteDue` is true, so silence draws each moment on its own envelope, and reduced motion never gates. `recentCuePeaks()` lists the first peak frame of each gate beside its carrying note's index and time.

## Adding a building

1. Add an entry to `BUILDING_DEFS` in `claudeville/src/config/buildings.js`. Copy a neighboring entry for the validated field shape:

   ```js
   {
     type: '<id>',
     x: <tileX>,
     y: <tileY>,
     width: <w>,
     height: <h>,
     label: '<UPPER CASE>',
     shortLabel: '<SHORT>',
     icon: '<glyph>',
     description: '<short>',
     district: '<district>',
     capacity: { work: <n>, ambient: <n>, overflow: <n> },
     visualTier: 'hero' | 'major' | 'minor',
     labelPriority: 'landmark' | 'standard' | 'low',
     entrance: { tileX: <tileX>, tileY: <tileY> },
     visitTiles: [workSlot(...), queueSlot(...), scenicSlot(...)],
     walkExclusion: [{ dx: <n>, dy: <n>, width: <n>, height: <n> }],
   }
   ```

   The local `workSlot`, `queueSlot`, and `scenicSlot` helpers create the visit-tile metadata expected by movement and occupancy systems. Tile coordinates must keep the footprint `(x..x+width-1, y..y+height-1)`, entrance, visit tiles, and walk exclusions within `0..MAP_SIZE-1` and not overlap water or another building footprint.

2. Add or reuse a `BuildingVisualRegistry.js` profile for label treatment, sprite IDs, decoration, emitters, lights, overlay anchors, and split-pass behavior. Keep procedural fallbacks in `BuildingSprite.js` narrow.

3. (Optional) If the building needs hover/click behavior beyond the default tooltip, subscribe in `IsometricRenderer.js` near the existing `_onMouseMoveMain` / `_onClick` handlers, or extend `BuildingSprite.hitTest`.

4. Run `npm run world:validate-buildings` and `npm run world:validate-terrain`, then reload the page. There is no build step; `App.js` adds buildings from `BUILDING_DEFS` on every boot.

Future building visual cleanup should expand the existing `BuildingVisualRegistry.js` coverage before adding custom procedural drawing. Good candidates are label accents/emblems, light sources, emitter specs, overlay anchors, and split-pass rules. Keep custom renderers behind named functions so adding a building usually changes config data rather than several distant `type` branches.

## Performance baselines and trail policy

Renderer comparisons use the manifest and runbook in [`../../../../docs/rendering-baselines.md`](../../../../docs/rendering-baselines.md). The matrix records WebGL, flattened PostFX, and allocation-free Canvas outputs from the same deterministic scene declaration, along with hardware, frame, upload/shader, resource-byte, and overlay-census evidence.

**Resident quality ladder (plan 0.1, V2).** Display pacing is the ladder's authority in both directions; the GPU timer is only a veto that confirms the GPU is involved.

- *Latched period.* The loop hands the ladder each rAF timestamp gap (`IsometricRenderer._loop` → `GpuWorldRenderer.notePresentInterval`). During the MINIMAL boot warm-up it takes p5 of 60 gaps (2–100 ms), snaps it to {60, 75, 90, 100, 120, 144, 165, 240} Hz and never re-derives it from achieved gaps, so a steady 60 fps on a 120 Hz panel still reads as missing. A screen or DPR change re-latches, `visibilitychange` clears the pacing window, and gaps above 4× the period are pauses, not misses. The veto budget is half the period (M26: 8.3 ms at 60 Hz, 4.2 ms at 120 Hz); `ladder.setBudgetMs()` replaces it until the next latch.
- *Demote.* One level, only when ≥ 20 % of the last 60 intervals exceed 1.5× the period **and** the median timing score (timer p25 plus upload, with the > 35 ms gap penalty) is over budget. Misses with a healthy timer are main-thread-bound (`missing:timer-under-budget`) and shed nothing. Without a timer (Safari, Firefox) the veto is waived.
- *Shedding didn't help.* The 60 intervals after a demotion must cut the miss share by a quarter; otherwise the step reverts and demotions hold for 60 s, doubling per repeat (cap 16 min). This ends the 3 ↔ 2 ↔ 1 ↔ 0 cycling.
- *Probe.* Above FULL, one level up once its backoff has elapsed (unless frames already miss with the timer over budget). The probe reverts as soon as its 60-interval window misses ≥ 5 % (baseline + 5 % when the lower level already missed) with the veto confirming, and is kept otherwise; failed probes back off 8 s, doubling to 64 s. Boot reaches FULL about 2 s after the latch at 60 Hz.
- *Return.* A Dashboard return resumes the last paced level at once (a pending probe's base level), keeping the latch and every backoff.
- *Timer.* The whole-frame `TIME_ELAPSED` query is begun on 1 frame in 4 (every frame while ≥ 10 % of the window misses, so an overload confirms within 2 s); the ladder reads the p25 of the last 30 samples.
- *Light admission* is the `EFFECT_BUDGET` row `light-admission` (FULL 128, REDUCED 64, MINIMAL 24, attention lights first; binned into 64×64 tiles of ≤ 16, 2.4), so the night's pools ship at every level.
- *Receipts* follow the V2 rule in the `EFFECT_BUDGET` header: K8 slopes (`node scripts/smoke/world-fps-benchmark.mjs --mode=kslope`), the vsync-unlocked FULL-vs-MINIMAL delta (`--mode=unlocked`) and per-level real-frame throughput (`npm run world:gpu-burst`), on a quiet host. Ladder acceptance: `--mode=soak`, `--mode=inject` and `--mode=dashboard`. The debug GPU-side load is also reachable by hand: `?gpuLoad=<passes>` (drawn at FULL only, a load the ladder can shed; add `&gpuLoadLevels=all` for every level) or `renderer.gpuWorld.setDebugLoad({ passes, levels })`.

Persisted movement history is retained for diagnostics and replay but routine historical trails are not painted over the village. The selected agent and action-needed agents may draw only a short, bounded recent route. `TrailRenderer.getDiagnostics()` reports the active policy, confirms zero ambient cache ownership, and retains stationary/manual-pan/follow/director-glide timing buckets. Run `npm run world:benchmark-trails` after changing trails or camera invalidation.

Shift-D reports PostFX source upload, mask upload, setup CPU, shader CPU/GPU, ladder decision/degradation reason, named GPU resource bytes, mask rebuild causes, and trail camera-mode timing. On the resident GPU world it additionally prints the active quality level and reason; the pacing rows (latched rate and period, misses in the window, paced level, veto budget and verdict, any pending probe or step, cool-down and next-probe countdowns); the whole-frame timer p25 beside its raw EMA and sampling cadence; the shed list (`shed (reason): id mode, …` from `EFFECT_BUDGET`, whose key order is the shedding order), which names every active cap — `light-admission` with its admitted/offered counts, at FULL too whenever the 32-light cap drops a light; per-pass GPU/CPU timings for `upload`, `occlusion`, `scene`, `bloom`, and `present` once `renderer.gpuWorld.setPassSamplingEnabled(true)` starts the one-pass-every-12-frames rotation (`EXT_disjoint_timer_query_webgl2`; disjoint samples discarded, unavailable never printed as zero; per-pass samples are not receipts on ANGLE-Metal); pinned versus evictable texture bytes with the live body-atlas size; and the agent-sheet row (B.2): equipped padded albedo sheets and their bytes against the 192 MB cap (48 M px), the pinned overage (on-screen profiles are never evicted, so bytes they hold above the cap print as `PINNED OVERAGE`), the released sheets with their retained LOD bytes, and the packed-geometry sheets. Only one backend's block is printed at a time so the inactive pipeline's zeroes cannot sit beside the active one's timings.

For World presentation changes, run `npm run verify:render` to capture deterministic screenshots and console evidence, then review the changed behavior on the operator-maintained server. Browser judgment remains manual; evidence capture does not.

## Frame and update notes

Astra carries Worldsplitter, her signature halberd, at every effort level. Effort reads through her distinct high-tier crests (the former effort floor rings and auras were removed with the other vector foot marks). Her armor and violet cape belong to the authored body and read strip; the halberd is composed separately through `AstraWeaponPose.js` with per-frame wrist coordinates. Read poses suppress equipment while both hands hold the book. Keep body, wrist profile, gauntlet palette, and portrait crop coherent when regenerating Astra.

- The render loop is plain `requestAnimationFrame`; one update tick per frame, no fixed timestep.
- Water shimmer advances from the shared visual elapsed clock and freezes when reduced motion is preferred. GPU water and wet-surface patterns use world coordinates, so camera movement does not drag the pattern across the surface.
- The terrain is baked into a `terrainCache` canvas by registered passes (`ground-splat`, `coast-field`, and the tile passes); only agents, effects, and weather redraw per frame. The bake key holds only what changes its pixels — cache bounds, asset availability, season, scenery revision, and each pass's revision — so a phase change or a zoom step reuses the cache; time of day and weather reach the ground and water through the grade and `waterMoodFor`. Adding terrain variation should register or extend a bake pass, not the per-frame path; call `invalidateTerrainBake()` when scenery changes. On the resident GPU path (B.2) the canvas lives only until the GPU holds its upload (`gpuWorld.hasResidentTexture`): `releaseTerrainCanvas()` drops the backing store and a same-size `gpuResident` stand-in keys the terrain record; a lost context, an evicted texture or the Canvas path re-bakes it once (`_getTerrainCache()` without `allowResident`).
- Equipped Codex sheets on the resident path (B.2): an albedo that only crowd (0.5x LOD) bodies sample is released 3 s after its last 1:1 use and its cache entry keeps the LOD sheet; a 1:1 body that needs it again recomposes it (same pixels) at most one compose per animation frame — inline for a selected, hovered or action-needed body, otherwise from the derived-art queue — and samples the LOD sheet at its own 1:1 size (each LOD texel two world texels) until its turn, so it never changes size. Composed, LOD and packed-geometry sheets, the agent atlases and dashboard avatars are CPU-backed (`willReadFrequently`) so Chrome keeps no GPU copy of the CPU sheets they draw (80-150 MB less GPU-process memory at dense-100 1080p). Cost: agent-atlas slot and walk-strip patches upload from CPU memory on the main thread, +0.18 ms/frame at dense-24 2560x1440 with 17 strips (noted beside `EFFECT_BUDGET`); B.1b/B.3 CPU cuts should count it.
- Event-bus subscriptions (`agent:added`, `agent:updated`, `agent:removed`) are stored in `_unsubscribers` and torn down in `hide()`. New subscriptions in this directory should follow the same pattern to avoid leaks across mode toggles.
- `ParticleSystem.setMotionEnabled(false)` is set when `(prefers-reduced-motion: reduce)` matches; respect this when adding new effects.
- New motion-bearing features must follow [`../../../../docs/motion-budget.md`](../../../../docs/motion-budget.md): check `motionScale` before allocating animation resources, declare a pulse band, and ship a static reduced-motion fallback.
- Use `PulsePolicy.js` helpers such as `pulseValue()` and `pulseAlpha()` before adding another repeating sine cadence. Local pulse math should be justified by a feature-specific need and still honor reduced-motion fallback values.
